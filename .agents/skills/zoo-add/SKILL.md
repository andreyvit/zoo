Preserve feedback without switching steps.

- Record feedback, briefly acknowledge, continue.
- Do not plan, review, implement, or fix it now.
- If feedback says current work is harmful, obsolete, destructive, or security/data-risky, stop and treat as interrupt.
- In task file: add clarification to `User request`; add `Log` line with deferred vs interrupting status.
- If deferred, add a subtask after the active one. Ready to run. No duplicates. Batch a bunch of tiny user-requested updates into one later subtask. If Subtasks do not exist yet, add to User request and the current plan so the later split includes it.
- Leave active subtask unless invalidated. Preserve original request baseline.
